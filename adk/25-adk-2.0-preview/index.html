    25 — ADK 2.0 Preview: Graph Workflows & Collaborative Agents¶

    Official docs: ADK 2.0 | Source: pip install google-adk --pre | Prereqs: 04-agents.md, 05-flows.md

    Note: AI-generated content, human-reviewed. May contain errors — verify against official docs.

    At a Glance¶

    ADK 2.0 adds three new capabilities on top of 1.x:
│
├── Graph-Based Workflows
│   └── Deterministic routing through explicit node/edge graphs
│       (replaces LLM-driven routing for predictable flows)
│
├── Collaborative Agents
│   └── Coordinator + subagent teams with 3 operating modes:
│       chat (full interaction), task (autonomous), single_turn (parallel)
│
└── Dynamic Workflows
    └── Programmatic control with loops, conditionals, checkpointing
        (async/await patterns instead of static graphs)

    ADK 2.0 is an alpha release adding graph-based workflows, collaborative agent teams, and dynamic workflows to the existing 1.x foundation. It is backward-compatible with 1.x agents but may have incompatibilities with advanced implementations. Do NOT share storage (sessions, memory, evals) between 1.x and 2.0 projects.

    For collaborative agents, dynamic workflows, and migration guidance, see 25b-adk-2.0-patterns.md.

    What's New in 2.0 vs 1.x¶

    ADK 1.x                                    ADK 2.0
├── LlmAgent + AutoFlow                    ├── All of 1.x (backward compatible)
│   └── LLM decides routing via            │
│       transfer_to_agent()                 ├── NEW: Graph-Based Workflows
│                                           │   └── Deterministic node/edge routing
├── SequentialAgent                         │       (code decides, not LLM)
│   └── Fixed linear order                 │
│                                           ├── NEW: Collaborative Agents
├── ParallelAgent                           │   └── Coordinator + subagents with
│   └── All sub-agents run concurrently    │       task/chat/single_turn modes
│                                           │
├── LoopAgent                               ├── NEW: Dynamic Workflows
│   └── Repeat until escalate              │   └── @node decorator, Context.run_node()
│                                           │       loops, conditionals, checkpointing
└── No deterministic routing               │
    (LLM always decides)                    └── NEW: Requires Python 3.11+

    When to Use 2.0 vs Stay on 1.x¶

    Should you use ADK 2.0?
│
├── Is this a production system?
│   └── YES → Stay on 1.x (2.0 is alpha — not production-ready)
│
├── Python < 3.11?
│   └── YES → Stay on 1.x (2.0 requires 3.11+)
│
├── Live streaming required?
│   └── YES → Stay on 1.x (graph workflows incompatible with streaming)
│
├── Open-ended chat / intent-based routing?
│   └── YES → LlmAgent + AutoFlow (1.x) is better
│
├── Simple linear pipeline?
│   └── YES → SequentialAgent (1.x) is simpler
│
├── Need deterministic routing (no LLM hallucination risk)?
│   └── YES → Graph-Based Workflows (2.0)
│
├── Need parallel agents with session isolation?
│   └── YES → single_turn mode (2.0 collaborative agents)
│
└── Need loops with checkpointing?
    └── YES → Dynamic Workflows (2.0)

    Graph-Based Workflows¶

    Official docs: Graph Workflows

    Nodes are agents, tools, or plain functions. Edges define the execution graph. Routing is deterministic — code decides the path, not the LLM.

    Sequential workflow¶

    from google.adk import Agent, Workflow, Event
from pydantic import BaseModel

# New in ADK 2.0: output_schema=str accepts bare Python types (str, int, etc.)
# ADK 1.x requires a Pydantic BaseModel subclass for output_schema.
city_generator_agent = Agent(
    name="city_generator_agent",
    model="gemini-2.5-flash",
    instruction="Return the name of a random city. Return only the name.",
    output_schema=str,  # New in 2.0: bare Python type accepted
)

class CityTime(BaseModel):
    time_info: str
    city: str

def lookup_time_function(node_input: str):
    return CityTime(time_info="10:10 AM", city=node_input)

city_report_agent = Agent(
    name="city_report_agent",
    model="gemini-2.5-flash",
    input_schema=CityTime,  # New in 2.0: structured input schema for graph nodes
    instruction="Output: It is {CityTime.time_info} in {CityTime.city} right now.",
    output_schema=str,  # New in 2.0: bare Python type accepted
)

def completed_message_function(node_input: str):
    # Note: Event in 2.0 is the same class as 1.x (google.adk.events.event.Event).
    # It supports convenience kwargs: message= (alias for content, auto-converted)
    # and route= (sets actions.route). These are NOT new fields — they are __init__
    # shortcuts that map to the existing content and actions fields.
    return Event(message=f"{node_input}\n WORKFLOW COMPLETED.")

root_agent = Workflow(
    name="root_agent",
    edges=[
        ("START", city_generator_agent, lookup_time_function,
         city_report_agent, completed_message_function)
    ],
)

    Conditional routing¶

    A router function returns Event(route=[...]) to pick which branch to follow:

    process_message = Agent(
    name="process_message",
    model="gemini-2.5-flash",
    instruction="Classify user message into 'BUG', 'CUSTOMER_SUPPORT', or 'LOGISTICS'.",
    output_schema=str,
)

def router(node_input: str):
    routes = [r.strip() for r in node_input.split(",")]
    return Event(route=routes)

def handle_bug():
    return Event(message="Routing to bug handler...")

def handle_support():
    return Event(message="Routing to customer support handler...")

def handle_logistics():
    return Event(message="Routing to logistics handler...")

root_agent = Workflow(
    name="routing_workflow",
    edges=[
        ("START", process_message, router),
        (router, {
            "BUG": handle_bug,
            "CUSTOMER_SUPPORT": handle_support,
            "LOGISTICS": handle_logistics,
        })
    ],
)

    Execution flow:
│
├── START → user message enters
├── process_message (Agent) → LLM classifies input
├── router (function) → returns Event(route=["BUG"])
└── route dispatch (dict) → handle_bug / handle_support / handle_logistics

    Multi-route fan-out¶

    A router can return multiple routes — all matched branches execute:

    def multi_router(node_input: str):
    return Event(route=["BUG", "LOGISTICS"])  # both fire

    Error handling in graph nodes — Production example: handling API timeouts with conditional routing¶

    from pydantic import BaseModel

class NodeResult(BaseModel):
    success: bool
    data: str | None = None
    error: str | None = None

def safe_api_call(node_input: str) -> NodeResult:
    try:
        result = call_external_api(node_input)
        return NodeResult(success=True, data=result)
    except TimeoutError:
        return NodeResult(success=False, error="API timeout")

def error_router(node_input: NodeResult):
    if node_input.success:
        return Event(route=["SUCCESS"])
    return Event(route=["FAILURE"])

root_agent = Workflow(
    name="error_handling_workflow",
    edges=[
        ("START", safe_api_call, error_router),
        (error_router, {"SUCCESS": process_result, "FAILURE": handle_error})
    ],
)

    Migration Notes¶

    Topic Detail
    Backward compatible 1.x agents work in 2.0 without changes
    Storage isolation NEVER share session/memory storage between 1.x and 2.0 projects
    Python version 2.0 requires Python 3.11+ (1.x works with 3.10+)
    Install pip install google-adk --pre (alpha, --pre required)
    Production Not recommended during alpha
